## 2026-09-21 — Email verification via a typed code (not Firebase's link flow)

- Firebase Auth only does clicked-link email verification out of the box; built a proper 6-digit-code flow on top instead, using Cloud Functions + Resend for the actual send.
- New Cloud Functions (`functions/src/index.ts`): `sendVerificationCode` (generates a 6-digit code, stores it at `emailVerificationCodes/{uid}` with a 10-minute expiry and a 30-second resend cooldown, emails it via Resend) and `verifyEmailCode` (checks the code, max 5 wrong attempts, and on success flips the *same* `user.emailVerified` flag Firebase's own link flow would have set — via `getAuth().updateUser(uid, { emailVerified: true })` — so nothing else in the app needs to know which mechanism verified the address).
- `firestore.rules`: new `emailVerificationCodes/{uid}` collection, fully denied to client read/write (function-only via the Admin SDK) — deployed live via `npx tsx scripts/deploy-rules.ts`.
- `contexts/AuthContext.tsx`: removed the old link-based `sendEmailVerification` call from `signUp`; added `sendVerificationCode()`/`verifyEmailCode(code)`, the latter force-refreshing the cached `user` object afterward (`reload()` + manual `setUser`) since Admin-SDK-side changes don't reach the client's `onAuthStateChanged` on their own.
- New screen `app/(auth)/verify-email.tsx`: 6-digit input, sends the first code on mount, "Resend" with a 30s cooldown, sign-out escape hatch.
- `app/_layout.tsx` auth guard: unverified + not-yet-onboarded users get routed to `/verify-email` before onboarding. Deliberately scoped to **new sign-ups only** — gating on `!hasOnboarded` too means anyone who already has a profile (every existing account, including whoever's been testing this app) is never touched by this, so nothing retroactively locks out people who already got in.
- **Blocked on a credential only the user has**: needs a free Resend account (resend.com, no credit card, 2 minutes) + `firebase functions:secrets:set RESEND_API_KEY`, then `cd functions && npm run deploy` — exactly the same shape as the still-outstanding `ANTHROPIC_API_KEY` situation. Sending defaults to Resend's shared test address (`onboarding@resend.dev`), which works immediately with no domain verification — fine for this demo.
